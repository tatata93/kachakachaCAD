# 開発待ち時間と検証の運用

状態: 進行中（2026-10-14）。オーナー依頼に基づく開発基盤整備。

## 今回の範囲と受入

1. Git管理された重点検証・短い整合検査・全体検証の入口、実行ID別のログと証拠を作る。
2. 実行予定と実績を照合し、0件、対象漏れ、失敗、予期しないskip、古い証拠を拒否する。
3. UI自己試験の一覧とケース別時間を出す。全件検証では重点フィルターを残さない。
4. 独立したCTestの代表群を逐次/並列で比較する。GUIと配布検証は省略せず資源を分離する。
5. 厚みツールの状態を専用非公開型へ移す代表例で、無変更/cpp/共有入力ヘッダー変更の増分ビルドを比較する。
6. Windowsの必須ゲート、配布版試験と通常起動を確認し、工程・構成・不要/削除ファイルの比較資料を添える。

担当は主担当兼実装1人と必要時の読み取り専用調査・品質確認各1人、合計最大3人。
サブ担当は対象版・質問・範囲を限定し、ファイル/Git変更、ビルド、試験、アプリ操作を行わない。
主担当が実行資源を管理し、古くなった読み取り結果を採用しない。別チャットを操作しない。

## 境界

この依頼はWP-12の開発・検証基盤と、WP-08の厚みUI状態の代表的分離に限定する。
他WPの公開幾何API、保存形式、製品動作、精度、Undo契約は変更しない。
自己試験用実行ファイルの全面分離と他ツール状態の全面移行は、効果と互換性の記録を残して後続にできる。
旧レビュー常駐を再開しない。他担当の作業、旧配布、バックアップ、増分ビルド資産は保全する。

## 検証段階

重点検証は作業ブランチの途中確認であり、全体検証済み配布版の証拠にはならない。
完成候補は全体ゲートと実際の配布物の検証を通す。mainの受入条件を緩和しない。
未知の変更・依存・試験選択は検証範囲を広げる。予定と結果の完全な対応を確認する。
同一論点や同一検証を、新しい変更・失敗・未確認事項なく繰り返さない。

## 比較の記録

既存の作業時間監査は過去の参考値であり、同条件の速度比較には使わない。
今回は同じPC/構成/並列数/対象で基準と変更後を比較し、キャッシュと負荷条件を記録する。
工程の並行を単純合算しない。分離不能な時間を内部思考時間と呼ばない。
実測結果と今後のコマンドは完了時に追記する。
