# ADR 0014: UI層をパネル単位のクラスへ分解する

## 背景

2026-08-31の外部調査で、`src/core` の幾何・モデルコアは健全である一方、UI層(`src/apps/cad/MainWindow.cpp`、11,758行)が肥大していると判明した。1ファイルに9枚のUIパネル構築、セルフテスト(約1,972行)、マニュアル用スクリーンショット生成(約647行)などが同居しており、変更のたびに無関係な処理を読み飛ばす必要がある。コア設計自体に問題はなく、作り直しは不要と判断した。

## 決定

- UI層はパネル単位のクラスへ分解する。`BuildDrawingPanel` 等の各パネル構築処理は、対応する `QWidget` サブクラスへ切り出す。
- `MainWindow` は個々のパネルの生成・配置と、パネル間・パネルとビューポート間の配線のみに縮退させる。パネル固有のロジックを `MainWindow` に残さない。
- セルフテスト(`RunCreationSelfTest`)やマニュアル用スクリーンショット生成(`PrepareManualScreenshot`)のような、UI配線そのものではない大きな処理は、別の翻訳単位(別ファイル)へ置く。
- 1つの `.cpp` ファイルへの追加が3,000行を超える見込みになったら、その追加より先に分割を行う。`MainWindow.cpp` への新規追加は原則禁止とし、新しいUIパネル・機能は独立したクラス/ファイルとして実装する。
- 具体的な作業手順と進捗は `docs/refactoring-plan.md` で管理し、都度更新する。

## 結果

パネルごとの変更が他パネルと無関係にレビュー・テストできるようになり、`MainWindow.cpp` の肥大が今後の変更で悪化しなくなる。移行は既存の「作業の原則」(挙動を変えるリファクタと機能追加を同一コミットにしない、移動は逐語的に行う、`check.ps1` と `--self-test` で検証する)に従い、パネル単位で段階的に進める。移行が完了するまでの間、新規パネルは新方式(独立クラス)で追加し、既存パネルは `docs/refactoring-plan.md` のチェックリストに沿って順次移す。

## ステータス

Accepted
