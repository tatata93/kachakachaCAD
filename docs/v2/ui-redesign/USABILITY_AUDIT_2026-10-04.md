# 2026-10-04 操作性調査と改善

## 方針
模型製作の完成品モデリング→近似→型紙/出力を短くする。
ツール→対象と事前選択の両方を保ち、右ペインは選んだツールの設定に限定する。
既存機能を探す・対象を絞って編集する共通操作を先に改善する。
主編集対象を表示メッシュへ置き換えず、大規模な履歴CAD化は行わない。

## 外部調査（公式資料）
- [Blender Menu Search](https://docs.blender.org/manual/en/3.0/interface/controls/templates/operator_search.html): 名前から操作を検索して実行する。採用: Ctrl+Kで全モード検索。
- [Blender Local View](https://docs.blender.org/manual/id/4.1/editors/3dview/navigate/local_view.html): 選択したものを独立した表示範囲で扱う。採用: 一時的な局所表示と明示的な解除。
- [Fusion 選択優先・フィルタ](https://help.autodesk.com/cloudhelp/ENU/Fusion-Model/files/SLD-SELECTION-PRIORITY-FILTERS.htm): 面・エッジ・本体などの選択を制御する。今回: 隠した対象を通常選択/スナップから除外。種類フィルタUIは未追加。
- [Inventor Property Panels](https://help.autodesk.com/cloudhelp/2023/ENU/Inventor-Help/files/GUID-3E5505B9-9F60-43A0-BCtrl+K2-97D183B91A70.htm): 選択入力から条件へ上から順に進める文脈依存パネル。既存統一方針を維持。全ツールの設定順の再配置は今後の個別点検対象。

## 現状で確認した問題と処置
| 問題 | 根拠 | 処置 |
| --- | --- | --- |
| 道具が増え、モードとカテゴリを知らないと探せない | OperationPanelHostの固定カテゴリ一覧 | 名前/カテゴリ/説明/ID検索、全モード切替、Enter起動 |
| 右の道具一覧に説明・使用可否が揃っていない | 独立したボタン生成 | QActionの説明、ショートカット、使用可否と同期 |
| 対象を選んでも古い無効理由が残る | RefreshCommandVisibilityはエラー時のみ説明更新 | 通常説明を毎回復元してから状態別理由を適用 |
| 選択だけ表示がワイヤ/点中心で面・立体・画像と不一致 | 各描画・選択経路 | 共通EntityShown判定を追加 |
| 選択を解除すると対象も消える | selectionOnlyは現在の選択集合 | 選択とは独立した局所表示を追加 |
| 全体表示が立体の寸法を含まない | FitToDocumentは曲線・点・画像のみ | 面・立体メッシュの境界も含め、選択ズームを追加 |

## 操作
Ctrl+K→文字入力→道具ボタン（またはEnter）。別モードでも対象の事前選択を維持して起動。
未選択時の右ペインは現在モードの一覧。全モード検索も選択可能。
「探す・表示」の局所表示は選択を固定した作業範囲。選択解除しても維持。
新規作成物は表示し、3D上の解除ボタンで戻る。文書の非表示属性・Undo履歴・保存内容を変えない。
出力対象は通常どおり明示選択する。局所表示だけでは出力範囲を指定しない。

視点に応じたズーム調整の回帰試験で、表示三角形の共有境界における厳密比較が丸め誤差で選択を落とす問題も確認。
MeshPickの重心座標に微小な許容差を加え、画面座標の往復・境界・明確な外側・視点後方を回帰試験する。
検索のキーは既存スナップのF3と衝突しないCtrl+Kとする。

## 残る課題
- 全ツールについて入力役割・設定順・連続作成の統一が完了したとはしない。複雑な製作/押し出し等は専用操作の検証を継続する。
- 種類別選択フィルタ/優先順位、ユーザーの設定プリセットは未追加。候補切替(Tab)は既存機能を使う。
- 今回の局所表示は通常の3D選択とスナップを対象とする。左ツリーの明示選択や専用干渉検査は独自の対象集合を持つ。
- 全画面サイズ・全テーマ・全ツールの組合せの目視評価は未実施。
