問題原因と対応検証
ツール中に別の線を削除するため道具を切り替える必要共通の「選択・削除」ボタンを追加。元の役割対象と編集中の点・数値を保存し、編集用選択を分離する。Ctrlクリックでも開始。Esc・ボタン・役割選択開始で復帰。実マウス/キーイベントで面作成、押し出し、厚み、投影、曲面押し出し、オフセット、寸法、画像の選択/削除/Undo/Redo/復帰。文字入力欄のDeleteは維持。
選択行のチェックが効かない・小さな手ぶれで大量選択押下時に切替えて解放をQtへ渡し、以前の押下状態で再処理されていた。チェックは安定した行IDで押下から解放まで所有し、同じチェック内で解放した時に一度だけ切替。修正前に再現失敗、修正後に同じ操作成功。個別/カテゴリ/グループ、折畳み、Undo、ドラッグ選択も確認。
投影途中の無関係な削除後も全入力の再選択が必要文書リビジョンだけで一律拒否していた。元線の全定義と選択フェイスのnative形状が変わらないことを照合できた場合に限り継続し、古い下見は再利用しない。入力済み線と面を残し、別の線を削除→復帰→投影→Undo後も投影可能。
巻付け曲線・平面部材の型紙が細分化巻付けの内部補間区間を元線区間内で結合。平面部材は元の円弧/円/Bezier/splineを外周・穴・折り線・切れ目へ戻して剛体変換する。無変形の接続線も元曲線を保持。円柱上の長い曲線、距離・長さ・閉鎖、傾斜/裏向き平面と穴、0/37/100%組立姿勢、複数の標本公差、保存再読込。
出力曲線の変形DXFのuniform splineにclampedノットを付けていた。SVG/DXFの円弧は法線符号を無視、PDFは負掃引の接線を二重反転。各writerを修正。書き出したノット・制御点から独立de Boor再構築。法線±Z×掃引±90度の向き・補弧・PDF接線を検査。
