# kachakachaCAD V2 UI/UX 統合実装仕様

## 0. この文書の位置付け

この文書は V2 の画面、選択、カーソル、入力、プレビュー、操作状態の正本である。
`ui-workflows.md` は個別機能の手順表、`command-catalog.md` はコマンドIDと入出力の正本とし、
操作上の意味が衝突した場合はこの文書を優先する。

出典はオーナー作成の「kachakachaCAD UI-UX 統合実装仕様書 v1.0」である。
2026-09-12 のオーナー決定に従い、次を統合時の確定事項とする。

1. `作図 / 部品 / 製作 / 出力` の固定4モードは必須ではない。より明快なら廃止する。
2. 利用者向けの `板材` 種別、板材モード、板材化コマンドは廃止する。
3. ワイヤーを Sketch または作業平面の所有物にしてはならない。
4. 操作順は `ツールを選ぶ -> 対象を選ぶ -> 値を入れる -> 確定` を標準とする。
   有効な事前選択がある場合の `対象を選ぶ -> ツールを選ぶ` も受け付ける。
5. スイープ、シェル、3Dフィレット、一般アセンブリ拘束、複数文書UIは将来課題とし、
   現在のUIへ空ボタンや無効メニューを置かない。

本書の `必須` と `禁止` は受入条件である。実装途中の移行UIは許すが、
受入時に二重の操作体系を残してはならない。

## 1. 利用者の作業モデル

利用者が直接扱う主要オブジェクトは次だけである。

- 作図点: 作図補助と寸法参照に使う3D点。
- 作業平面: 2D入力を置く一時的な座標基準。ワイヤーの所有者ではない。
- ワイヤー: 3D空間に独立して存在する線、曲線、連続鎖、閉輪郭。
- 形状ガイド: 輪郭・断面ワイヤーから作る参照曲面。物理部品ではない。
- 部品: 1つの連結した閉ソリッド。
- 製作モデル: 完成品を実際に作れる部材へ近似した派生モデル。
- 型紙: 製作モデルを切り出すための2D展開結果。
- グループ: 表示、選択、整理、作業中の所属先をまとめる容器。

材料、厚さ、紙、プラ板、曲げ許容値は部品または製作モデルの属性であり、
別の `板材` オブジェクトを作らない。

基本工程は次の一方向の流れとして見せる。

1. ワイヤーを作図する。
2. 閉輪郭の押し出し、形状ガイドの厚み付け、輪郭群の閉空間認識で部品を作る。
3. 必要な曲面を製作用の大きな連続部材へ近似する。
4. 製作モデルを曲げ確認し、型紙または3D形式へ出力する。

利用者は工程名を覚えなくても、選択対象とプロパティから次の操作へ進めなければならない。

## 2. 画面構成

### 2.1 常設領域

常設する主要領域は次の4つだけとする。

1. 上部: メニューバーと1段のコンパクトな道具バー。
2. 左: モデルツリー。検索、表示、ロック、作業中グループを含む。
3. 中央: 3Dビューポート。
4. 右: コンテキストプロパティ。選択対象または実行中ツールの一方を表示する。

下端には短いステータスバーを置く。常設の巨大なコマンド棚、リボン、
左下の長文操作パネル、部品と製作で重複するボタン群は禁止する。

### 2.2 メニュー

トップメニューは次を基準とする。

- ファイル
- 編集
- 表示
- 作図
- 3D
- 製作用近似
- 出力
- ツール
- ウィンドウ
- ヘルプ

未実装機能を有効な項目として表示しない。将来機能の場所を示す目的で無効項目を並べない。
同じコマンドを複数箇所へ置く場合も、同じCommandId、同じ有効条件、同じToolSessionを使う。

### 2.3 上部道具バー

常時表示するのは次に限る。

- 新規、開く、保存
- 元に戻す、やり直す
- 選択フィルター
- 作図面
- 作業中グループ
- スナップ切替
- よく使う作図、押し出し、測定、製作用近似、出力への入口

固定4モードのタブは最終UIから外す。移行中に残す場合、モード切替時に実行中ツールを終了し、
以前のツールを選択状態のまま残してはならない。通常選択は明示的に消さない限り保持してよい。

### 2.4 右プロパティ

右領域は同じ場所で次のどちらかを表示する。

- 通常時: 選択したオブジェクトまたはサブ要素のプロパティ。
- ツール中: 現在のToolSessionの入力、選択済み対象、プレビュー、確定、取消。

コマンド専用パネルを別の場所へ常設しない。ツール終了時は選択プロパティへ戻る。
複数選択時は共通属性だけを表示し、混在値は `複数` と表示する。

## 3. 意味状態と描画

見た目はデータ種類より状態を優先する。最低限、次の状態を別の色と線幅で表す。

- Default: 通常表示。
- Hover: カーソル直下の候補。選択とは異なる軽い強調。
- Selected: 通常選択。
- Input: 実行中ツールへ取り込まれた確定入力。
- Preview: まだ履歴へ入っていない生成結果。
- Warning: 許容できるが注意が必要な状態。
- Error: 確定不能な状態。
- Locked: 参照できるが変更できない状態。
- Hidden: 非表示。

必須規則:

1. Hoverだけで選択を変更しない。
2. SelectedとInputを同じ色にしない。
3. Previewは確定済み形状より薄くし、点線または半透明を併用する。
4. Errorは赤だけに依存せず、短い理由文と問題位置の強調を併用する。
5. 作業平面は形状より弱く描画し、非アクティブ面はさらに薄くする。
6. 選択点とスナップ点は画面上の一定pxサイズとし、ズームで見失わないようにする。

色の具体値はテーマ定義へ置く。標準テーマとWindows 95テーマで意味状態を変えない。

## 4. 選択モデル

### 4.1 選択参照

選択はEntityIdだけでなく次を保持する強い型とする。

- EntityId
- SubElementKind: Object / Vertex / Edge / Face / ControlPoint / WorkPlane
- 安定したSubshapeKeyまたはSegmentId
- ヒット位置
- ヒット時の画面距離

同じオブジェクトの複数の端点、線分、面を同時に選べなければならない。
表示名やツリー行番号を参照キーにしない。

### 4.2 基本操作

- 左クリック: 1候補を選択。空白なら通常選択を解除する。
- Ctrl+左クリック: 候補を追加または解除する。
- 左ドラッグ: 矩形選択。
- 左から右の矩形: 完全に含まれる対象だけ。
- 右から左の矩形: 交差した対象も含む。
- Tab: 同位置の候補を順送りする。
- Alt+クリック: より奥の候補を選ぶ。
- 右クリック: コンテキストメニュー。近傍候補が複数なら候補一覧を先頭に出せる。

Shiftは選択集合の追加に使わない。作図中の方向・角度・軸拘束へ使う。

### 4.3 候補優先順位

既定の優先順位は次とする。

1. 入力中ツールが要求する型。
2. 端点または作図点。
3. 幾何交点。
4. 曲線上の最近点。
5. エッジ。
6. 面。
7. オブジェクト全体。
8. グリッド点。

同じ優先度では画面上の距離が近いものを優先する。隠れた面を画面手前の面より先に選ばない。
候補が曖昧な場合は勝手に確定せず、Tab、Altまたは右クリック候補一覧で選び直せる。

### 4.4 選択フィルター

`自動 / 点 / ワイヤー / 面 / 部品 / 製作モデル / 作業平面` を用意する。
フィルターは選択可能性だけを変え、表示やデータ所有関係を変えない。

## 5. カーソルとマウス

### 5.1 カーソル

- 通常選択、形状Hover: 矢印。
- パン: 開いた手、ドラッグ中は閉じた手。
- 回転: 回転を示すカーソル。
- 作図点配置: 十字。
- 移動、回転、寸法編集: 対応する専用カーソル。
- 禁止対象: 禁止カーソル。
- クリック可能な通常形状に指カーソルを使わない。

カーソル変更だけで状態を伝えず、Hover強調と短いラベルを併用する。

### 5.2 カメラ

- ホイール: カーソル位置を基準にズーム。
- 中ボタンドラッグ: パン。
- Shift+中ボタンドラッグ: オービット。
- 右ドラッグ: カメラ操作に割り当てない。
- 右クリック: コンテキストメニュー。

カメラ操作中にツール入力や選択を誤確定しない。自動慣性、地平線補正、
90度吸着は既定で無効とする。

## 6. スナップと作図拘束

### 6.1 スナップ

スナップ候補はクリック前にリングと短いラベルで示す。リングは候補種別で形を変え、
確定時だけ一瞬強く表示する。

既定の優先順位は次とする。

1. 端点、作図点
2. 交点
3. 中点、中心、四分点
4. 曲線上の最近点
5. 垂足、接点
6. グリッド

吸着半径は画面px基準とし、通常候補と現在ツールに適合する候補で強さを変える。
主点へ常時強く引き寄せず、Hover時に候補を示してクリックで確定する。

### 6.2 一時解除と拘束

- Shift: 水平、垂直、軸、角度など現在ツールの方向拘束。
- スナップ一時解除: `S` を押している間。
- スナップ常時切替: 上部の磁石アイコン。

既存実装の `Shiftで全スナップ解除` は廃止する。Ctrlは選択集合専用であり、
スナップ解除へ流用しない。

## 7. ToolSession

### 7.1 共通状態

全ての対話ツールは共通のToolSessionを使い、最低限次を保持する。

- CommandId
- Phase
- RequiredInputs
- AcceptedSelectionKinds
- CapturedInputs
- Parameters
- PreviewResult
- Diagnostic
- CanCommit
- CanStepBack

ツールごとの巨大なif文で同じ状態遷移を再実装しない。ツール固有部分は入力定義、
プレビュー計算、確定Commandの生成に限定する。

### 7.2 標準遷移

標準遷移は次とする。

`Idle -> AwaitingInput -> EditingParameters -> PreviewReady -> Committed`

エラー時は `InvalidPreview` とし、ツールを終了させない。入力を直すと同じセッションで再計算する。

### 7.3 操作順

標準はツール先行である。

1. 利用者がツールを選ぶ。
2. 右プロパティとビューポート左上に必要な対象を表示する。
3. 対象をクリックするとInput状態になる。
4. 値を入力するたびにプレビューする。
5. Enter、右プロパティの確定、またはツール固有の完了操作で履歴へ追加する。

事前選択が必要型と個数を満たす場合は、ツール起動時にその選択をInputへ取り込む。
満たさない選択は削除せず無視し、不足対象を明示する。コマンドボタン自体を無闇に無効化しない。

### 7.4 終了と戻る

- Esc 1回: 現在の入力段階を1つ戻す。
- 戻せる段階がない状態でEsc: ツールを終了する。
- ツールがない状態でEsc: 通常選択を解除する。
- Backspace: ツール内の直前入力を戻す。
- Ctrl+Z: ToolSessionに戻せる入力があればそれを戻し、なければモデル履歴を戻す。
- Enter: 有効なプレビューを確定する。
- Delete: 通常選択を削除する。ツールの取消には使わない。

ツール切替時は前のToolSessionを終了する。古いツールの選択表示、プレビュー、数値入力を残さない。

## 8. 数値入力

数値入力は右プロパティを正本とし、作図中はカーソル近傍へ同じ値を表示する。
値は双方向同期し、どちらを編集しても1つのToolSessionパラメータを更新する。

必須条件:

- `(180/2)*3` のような四則演算と括弧を受け付ける。
- 長さはmm、角度はdegを既定表示とし、内部単位へ変換する。
- 不正な式、0除算、範囲外は確定不能にし、入力欄の近くへ理由を表示する。
- マウス移動だけで入力フォーカスを奪わない。
- ツール開始後、最初の必須数値を入力できる段階ではその欄へフォーカスできる。
- Tabで次の欄、Shift+Tabで前の欄へ移動する。
- プレビュー再計算は短いdebounceを入れ、古い計算結果を破棄する。

## 9. 作業平面とワイヤー

作業平面は入力座標系であり、ワイヤーの親ではない。

1. 作業平面を切り替えても既存ワイヤーの所有者、UUID、3D座標を変更しない。
2. ワイヤーは作成時の平面を任意の参照メタデータとして記録してよいが、削除連鎖の親にしない。
3. 作業平面を削除してもワイヤーを削除しない。再編集に必要なら診断を出して別平面を指定させる。
4. モデルツリーでワイヤーをSketchや作業平面の子へ入れない。
5. グループは所有関係ではなく整理と表示の集合である。

作業平面は全体表示切替と個別表示切替を持つ。アクティブ面は明瞭に、他は非常に薄く表示する。
正対コマンドはカメラだけを変え、形状を移動しない。

## 10. 現在範囲のツール契約

### 10.1 作図

対象は直線、ポリライン、円、円弧、Bezier、通過点B-spline、作図点、トリム、延長、
分割、結合、端点一致、接線接続、曲率接続、移動、回転、鏡像、測定とする。

各ツールは開始時に必要な点数または線数を示す。複数選択が必要なツールは、入力済み件数と
次に選ぶ種類を表示する。確定済み入力だけをInput色にし、通常選択と混同しない。

### 10.2 形状ガイド

閉輪郭、2断面、複数断面、2本以上の外形ガイドと1本以上の断面ガイドを扱う。
1役割が複数線分で構成される場合は、自動連結鎖または明示した複数線分を1入力として扱う。
端点接続、両端接続、外形と断面の交差を許容差で検査し、順序と向きをプレビューで示す。

### 10.3 押し出し

押し出しは閉輪郭または形状ガイドを入力とし、出力を次から選ぶ。

- 部品: 閉ソリッドを作る。
- 形状ガイド: 面だけを作る。
- ワイヤー: 入力輪郭の複製と対応する接続線だけを作る。
- 部品+ワイヤー: 同じ評価結果から両方を作る。

`ワイヤー` 出力に面やソリッドを混ぜない。入力は削除せず、既定は表示を維持する。
`生成後に入力を隠す` は表示属性だけを変える明示オプションとする。

### 10.4 閉空間から部品

利用者が境界ワイヤーを手動指定する方法と、選択範囲または全体から閉じた立体輪郭を検出する方法を持つ。
自動検出結果は確定前に境界、向き、隙間、重複、自己交差を表示する。
非閉鎖、非多様体、複数領域の場合は落とさず理由番号付きで断る。

### 10.5 形状ガイドから部品

形状ガイドを法線方向または指定方向へ厚み付けして部品を作る。
利用者向け名称は `厚みを付けて部品化` とし、`板材化` と呼ばない。
片側、反対側、両側、選択面までを扱う。自己交差や厚みが曲率半径を超える場合は
安全な代替値を勝手に採用せず、問題箇所と理由を示す。

### 10.6 製作用近似

入力は完成品の部品、形状ガイド、接続維持に使うワイヤーとする。
出力は別オブジェクトの製作モデル、可変曲げ状態の境界ワイヤー、形状ガイド、型紙である。
三角形メッシュを利用者の主編集対象にしない。大きな連続部材を優先し、必要な箇所だけ切れ目、
V字または曲線側辺の切れ込み、追加分割を使う。

組立率0から100%で実長を維持し、任意状態を固定して2D/3D出力へ渡せる。
窓、ライト、扉などの開口を境界越しでも保持する。

### 10.7 出力

現在選択、グループ、部品、製作モデル、型紙から出力対象を明示する。
形式は対象に適合するものだけを表示する。確定前に対象数、閉鎖性、単位、実寸、
最大/RMS偏差、出力先を要約する。

## 11. プレビューと履歴

プレビューはDocumentへ追加しない一時評価結果とする。確定時だけ1つのCommandとして履歴へ入れる。

1. パラメータ変更で入力オブジェクトを直接変更しない。
2. 非同期評価には世代番号を付け、古い結果を表示しない。
3. 取消時にプレビュー用EntityIdをDocumentへ残さない。
4. 確定後のUndoは入力、生成物、表示属性変更を1単位で戻す。
5. 再編集可能なのは依存入力とパラメータを保持するFeatureだけとする。

## 12. エラーと診断

エラーは次の4点を同時に示す。

- 何ができなかったか。
- なぜできなかったか。
- どこが問題か。
- どう直せるか。

幾何的に不可能な場合は理由番号をcoreで生成し、`diagnostic-catalog.md`へ登録する。
UI文字列だけの理由や例外本文をそのまま表示しない。エラーでアプリを終了させず、
ToolSessionを修正可能な状態に保つ。

## 13. 性能

- Hoverは通常フレームを妨げないこと。重い再評価を行わない。
- 数値編集のプレビューは入力停止後に開始する。
- 長い評価は取消可能にし、進行中であることを右プロパティに表示する。
- 選択探索は表示キャッシュまたは空間索引を使い、Document全走査をマウス移動ごとに行わない。
- 1万ワイヤー規模でも選択とカメラ操作が実用速度を保つことを性能試験へ追加する。

## 14. DPI、サイズ、画面復元

1. 100%、125%、150%、200% DPIで文字、アイコン、クリック領域が欠けない。
2. アイコンボタンは最低24 logical px、主要操作は28 logical px以上の押下領域を持つ。
3. 狭い画面では道具バーを折り返さず、優先度の低い項目をオーバーフローへ移す。
4. ドックの最小幅を定め、文字を1文字幅まで潰さない。
5. ウィンドウ位置とドック配置を保存する。
6. モニターが消えた場合は見える画面内へ復元する。
7. `表示を初期配置に戻す` をウィンドウメニューに置く。

## 15. アクセシビリティと説明

- アイコンだけのボタンには短いツールチップとアクセシブル名を付ける。
- 色だけで選択、警告、エラーを区別しない。
- キーボードだけで右プロパティの主要入力と確定、取消へ移動できる。
- 画面へ機能説明の長文を常設しない。
- ツール中はビューポート左上に `ツール名 / 現在の手順 / Escで戻る` を2行以内で表示する。
- 詳細な使用例はHTMLマニュアルへ置き、F1で現在のCommandIdに対応する箇所を開く。

## 16. 現在の非目標

次はデータ契約を妨げない範囲で将来追加できるが、WP-14では実装しない。

- スイープと可変断面スイープ
- シェル
- 一般的な3Dフィレット、面取り
- 本格的な寸法拘束ソルバ
- 一般アセンブリ拘束と干渉解析
- 複数文書タブ
- マクロ、プラグイン、コマンド検索
- 自動ネスティングとのりしろ

未実装機能のボタン、空パネル、完成したように見えるダミープレビューを置かない。

## 17. 禁止事項

1. ワイヤーをSketchまたは作業平面の子として所有させること。
2. `板材` を利用者向けオブジェクト、モード、作成コマンドとして復活させること。
3. ツール切替後も以前のツールを選択状態で残すこと。
4. 事前選択がないだけで、対象選択型ツールを一律無効にすること。
5. EntityIdだけでサブ要素選択を潰すこと。
6. Shiftをスナップ全解除へ割り当てること。
7. 右ドラッグをカメラ操作へ割り当てること。
8. PreviewをDocumentへ仮登録して取消時に削除する設計。
9. 同じコマンドを場所ごとに別ロジックで実装すること。
10. 高度機能の空ボタンを先に並べること。

## 18. 実装フェーズ

### Phase 0 規範統合

- 本書、ADR、product-contract、ui-workflows、受入試験、追跡表を一致させる。
- 現行実装との差分を未達として記録する。

### Phase 1 操作基盤

- SubElementを保持するSelectionRef。
- SelectionServiceと選択修飾キー。
- Hover/Input/Previewの意味状態。
- カーソル、マウス、候補循環、スナップ修飾キー。
- 共通ToolSession、Esc、Enter、Backspace、Ctrl+Z。

### Phase 2 画面骨格

- 固定4モードを廃止し、メニューとコンパクト道具バーへ統合。
- 右コンテキストプロパティへ選択とツール入力を統合。
- 重複ボタンと常設説明パネルを除去。
- DPI、オーバーフロー、ドック復元。

### Phase 3 ツール移行

- 作図、編集、測定。
- 形状ガイド。
- 押し出し、閉空間部品化、厚みを付けて部品化。
- 製作用近似、曲げ確認、出力。

各ツールは旧個別状態機械を残さず、共通ToolSessionへ移す。Phase 3は機能群ごとに
build、ctest、self-testを通して小さくpushする。

### Phase 4 実用受入

- ER1/初期ER2 1/87前頭部モデルで作図から出力まで通す。
- 100%、125%、150%、200% DPI画像試験。
- マウスとキーボードの操作表をHTMLマニュアルへ反映。
- V1とV2を比較し、V1だけにある必要機能を一覧化する。

## 19. 受入の要点

次を1つでも満たさない場合、UI全面改訂は完了ではない。

1. ツールを選んでから複数の端点、線分、面を順番に取り込める。
2. 有効な事前選択から同じツールを開始しても同じ結果になる。
3. ツール切替で古いツール、プレビュー、入力値が残らない。
4. Ctrlでサブ要素を複数選択でき、Shiftは作図拘束になる。
5. Hover、Selected、Input、Previewを目視で区別できる。
6. ホイール、中ドラッグ、Shift+中ドラッグ、右クリックが本書どおり動く。
7. 作業平面を削除または切替してもワイヤーの所有と3D座標が変わらない。
8. `板材` という利用者向け種類、モード、作成コマンドがない。
9. 押し出しで部品、形状ガイド、ワイヤー、部品+ワイヤーを明示選択できる。
10. Esc、Backspace、Ctrl+Zの範囲が一貫している。
11. 形状エラーが理由番号、問題箇所、修正案を示し、アプリが継続する。
12. DPI変更と画面構成復元で操作不能な領域が生じない。
