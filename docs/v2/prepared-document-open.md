# 保存文書を安全に開くための再構築（2026-10-11）

状態: 実装済み、全体検証待ち。担当は実用検証タスク、WP-10の文書読込と既存再構築の境界。
118（88839cc2f）は元の起動先と独立した復旧用記録へ保全済み。

## 問題と方針

現在のOpenDocumentFileはAdoptDocumentで文書とUndo履歴を置き換えてから、
RebuildKernelShapesで派生形状を消して順に再計算する。
この途中で処理だけを取り消すと、元文書へ戻れず、部分的な形状が残る。

保存されたV2文書を開く際は、専用の子プロセスで既存の読込・再構築処理を実行する。
子は読み取った文書のコピーと自身のカーネルキャッシュだけを操作する。
元ファイルへの保存は行わない。既存の再構築経路を共用し、別の幾何アルゴリズムは作らない。
表示は現在の処理名、処理対象、完了した段数、経過時間と取消だけにする。
一段の内部計算の進捗率を推測して表示しない。

成功時は元の編集可能な文書と、再計算したBRep・境界・面標本・製作近似結果を転送する。
転送は一時的な版付き形式であり、kcd2の保存形式は変更しない。
文書のFeature定義を凍結形状へ置換して保存することはしない。
親で入力と結果を検証し、すべての形状を準備してから文書と派生キャッシュを一括採用する。
途中結果、異常終了、不完全な転送、開始時と異なる文書revisionは採用しない。

取消は所有する計算子プロセスだけを終了し、その一時結果を破棄する。
親の文書、Undo履歴、表示、保存先、既存形状を変更しない。失敗後も別の文書を開ける。
再構築できない形がある場合も、部分成功として元文書を置換しない。
親へ転送したBRepの復元・画面への採用には短い同期処理が残り、その時間は検証で測る。

## 検証と境界

- 小さな通常履歴、重い曲面オフセットを含む最小履歴、再構築に失敗する履歴を使う。
- 読込中のUI応答、実計算中の取消、計算子の異常終了、再試行を確認する。
- 元文書の内容、revision、Undo/Redo、保存先、カーネル形状が失敗前後で不変か確認する。
- 成功時の元Feature定義、ID、寸法、形状、近似部材、型紙を保存再読込で比較する。
- 118の既存モデルを利用して互換性を確認する。大規模な貨車の完成は目的にしない。
- 一般GUIと配布試験が合格するまで、通常起動先やリモートへ未検証コードを反映しない。

初期範囲はV2の保存文書を開く操作。V1スクリプトのインポート、編集中の全履歴再評価、
新規の面生成や出力のすべてが取消可能になったとは報告しない。

## 対象経路の確認

Windows GUIのHP-OPEN 5ケースを追加。滑らかな壺の面と厚みFeatureを保存した文書を開き、実計算中のEsc、計算子の異常終了、無効なBRep、未対応のねじれ帯による再構築失敗を検査する。元文書は別の厚み付き立体を持つ。取消前後の正本文書JSON、revision、表示形状数、カーネルキャッシュ数、Undo/Redo、保存先、入力ファイルの同一性と再試行を確認した。5/5合格。

Escケースは別の編集ツールが有効な状態から開始し、開始から復帰まで582ms、UIタイマー98回、表示形状2→2、キャッシュ5→5だった。これはキー入力から復帰までだけの時間ではない。メタデータ・未知の書庫エントリ保持も検査した。既存HP-THは7/7合格。全GUI・配布試験が合格するまで通常起動版への反映は保留する。
