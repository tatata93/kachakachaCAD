# Implementation

Boundary: the viewport keeps the candidate list and the commit; the window only shows the menu.

- `SetContextMenuCallback` now takes `std::optional<int>(const QPoint&, const std::vector<QString>&)`. The viewport passes the click's global position plus the candidate captions and gets back only a candidate index.
- `V2Viewport::CandidateLabels()` builds captions from the existing `cycle_` (UI-P1-003 collection) — Document `displayName` + Japanese element kind (`CandidateKindNameJa`) + owning group (`ui-workflows.md` §3.2), with ` #n` appended to any captions that would otherwise collide, so same-named objects and other segments/faces of one object stay distinguishable. Candidates keep their `PickCandidate` (SegmentId/SubshapeKey intact); only an index crosses the boundary.
- `V2Viewport::SelectCandidate(index)` moves `cycle_.index`, syncs Hover, and applies `ApplySelection(..., SelectionMode::Replace)`, then reports through the shared new `ReportSelectionCount()` that `SelectAt` also uses — same status text and selection-changed notification as a normal click.
- `PressRightWithoutMoving(position)` refreshes the pick cycle at the right-click's local position, passes captions only when ≥2 candidates, and touches the selection only if a candidate was chosen (blank/1-candidate right-click keeps the selection and still gets the ledger menu). The old no-arg form remains and forwards the last cursor position, so the measure-tool self-test path is unchanged.
- `V2MainWindow::BuildSelectMenu(QMenu&, labels)` prepends a "この場所の候補" section with the captions and a separator, then the unchanged ledger entries; `ShowSelectMenuWithCandidates` execs it and maps the chosen action back to an index. `ShowSelectMenu` (tree right-click) delegates with no candidates. No command ledger was duplicated.
- Right button is out of the camera: `mousePressEvent` no longer sets `panning_` for it; it records `rightPressed_`/`rightPressPosition_` (ignored while a control-point or body drag is live). `mouseMoveEvent` only measures the distance via core `DragIsFarEnough` (4px) and moves nothing; `mouseReleaseEvent` opens the menu only under that threshold. Middle drag pan and Shift+middle orbit are untouched; the now-dead `viewDragMoved_` was removed.
