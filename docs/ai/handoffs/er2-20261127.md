# ER2の継続開発を学校PCへ引き継ぐ

2026-11-27のオーナー指示。学校PCのCodexを、ER2関係の調査・修正・検証・モデリングの実行担当にする。
自宅は保存済みコードの固定検証、受渡し、結果確認、統合を担当し、同じ製品箇所を同時に編集しない。
単なる環境確認や一般的なUI巡回で終わらず、添付ER2の作業を最優先で続ける。

## 入力データ

原本を変えず、3つの保存版と再開メモを受渡し用ZIPへまとめた。
公開ブランチにはモデルを追加していない。既存リポジトリの未公開draft releaseを使う。
draftは公開・latest化しない。認証なしのrelease/asset取得が404であることと、公開latestが不変であることを確認した。

## コードの基点と既存成果

基点は `codex/v2-wp01-build-scaffold` の
`be44649090add1a302dfacece350817a88e7c629` を含む版。初回に取得したmainはその祖先である。

既に実装した修正は、3点作業面の取得点精度、有限曲線と作図面の実交点、
Tab/右候補の点入力対象、Ctrl/取消/ツール切替の持越し、元の輪郭線の直接選択、
同一比較内の完全に同じ近似候補の再計算省略。
古いmainへこれらを修正し直さず、最新の実装で追加の失敗を再現した場合だけ直す。

自宅の全体ゲート `er2-point-plane-windows-20261127c` は、この引継ぎ時点では進行中。
配布UI1112例は成功し、開発UI・残りのCTestは未完了。全体成功や公開済みとは扱わない。
以前のrun a/bの不合格・中断を成功へまとめず、検証結果は対応するコミットとバイナリに結び付ける。

## 変える対象と残す対象

変える対象は、誤った交点から作った辺、ねじれた窓面、ずれたオフセット、
窓と周囲面の境界不一致、およびそれらの作成を妨げるCADの不具合。
原本、未編集の車体輪郭、参考の曲線、UUID、参照、既存形状を意図せず変えない。
ERの元の寸法を守り、115系での幅36mm指定をERへ適用しない。

窓面は平面とし、その頂点は実際の有限な車体輪郭上に置く。
四辺が直線でも四隅が非共面なら平面ではない。接平面への投影で元面との位置差を隠さない。
隣接部は頂点だけでなく共有する辺全体を一致させ、穴・Hゴム・枠のオフセットは同じ平面内で作る。

## 既知の形状と未採用の案

従来入力の正規の下側輪郭は末尾0084、上側は0095。079e/07b0は別の参考曲線なので区別する。
旧外側窓は最小二乗平面から最大約0.14985mm、三隅の平面から残りの隅が約0.6111mm外れる。
旧中央窓の最小二乗平面誤差は約0.003341mm。名前だけで平面性を判断しない。
窓の直線辺と古い周囲面の円弧との間には約0.945/0.557mmの隙間がある。

再開メモの候補は、上下円弧の中心から同じ方向の半径を使い、有限な実交点を対応させて
平面の窓パネルを作る方法。外角が約3.28mm動く案なので、見た目と資料を照合してから採否を決める。
この案は完成モデルではない。曲線を有限端の外へ延長してつじつまを合わせない。
窓を作り直したら、上・下の周囲面も窓パネルと同じ共有辺で張り直す必要がある。
元のライト参考線を残し、支持面を変えた部分の実際の開口・座を確認する。

## 作業順序と成果物

1. 開発環境の残件を解消し、受領した添付と現在の開発版で失敗を再現する。
2. 必要なソフト修正を行い、添付由来と一般化した条件で重点検証する。
3. 添付範囲の前頭車体を理想モデルとして整える。平面窓、開口、枠、共有辺を確認する。
4. 近似機能で製作用モデルへ進む。額と前面下部の3D曲面は積層ではなく、少数の一方向に曲げられる板にする。
5. タミヤのプラ板を切断・曲げ・必要な部分の積層・接着で作れるか確認し、平板型紙を出す。
6. 理想・曲げ板近似・型紙を区別して保存し、操作手順、板厚・材料、部品と接着辺、最大/RMS誤差を記録する。

強拡大で実曲線・描画・交点・隙間を確認する。取消、連続ツール、Undo/Redo、保存再読込も照合する。
全体/配布ゲート、STEP等の形状出力、原寸型紙の必要な検証を完成候補で行う。
実材での組立は、実施した場合にだけ実証済みとする。

## 高速反復と所有

[自宅・学校PCの開発運用](../home-school-workflow.md)を適用する。
調査・編集・ビルド・多数条件の回帰はCLI・増分・自動試験を既定とし、
実マウスは選択・スナップ・見た目・ツール遷移等の必要な代表箇所に絞る。
模型の作成経路は人間が再現できる通常UIまたは既存のUI再生で記録する。
座標注入やモデルファイルの直接生成を、作図できたことの代用にしない。

着手前に学校側でWP-08の限定所有を正本へ記録してcommit/pushする。
他WPの修正が必要なときは1WPずつ順に所有を移す。自宅は同じ箇所を編集しない。
各一区切りの修正と検証をpushして次へ進み、総時間と待ちの内訳も残す。
原本の受領・一致と、モデル完成・配布成功は別の状態として報告する。
