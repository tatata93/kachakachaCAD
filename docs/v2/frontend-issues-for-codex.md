## FI-001 曲線網(U/Vネットワーク)の入力欄が正本に無い

正本(`kachakachaCAD_extrude_surface_UI_final_mock.html`)の「面を作る」は
入力欄が3つ(断面 / ガイド / 境界)で、作り方のカードに「曲線網 U/Vネットワーク」
がある。**U と V を別々に入れる欄が無い。**

いまの実装は、正本の「案内付きロフト = 断面 + ガイド」と同じ読み方で
「断面 = U、ガイド = V」としている(`RoleForSurfaceSlot`)。欄は増やしていない。
別の割り当てにするなら core 側の `RoleForSurfaceSlot` を変えれば済む。

## FI-002 平面の「穴」を画面から入れられない

平面(`PlanarBoundary`)が使う役割は 外形 と 穴 の2つだが、
3つの欄では外形しか表せない。穴のある平面は、後ろの役割表からしか作れない。
「面を作る」を入口1つに統合した意味が、穴のときだけ崩れている。

## FI-003 「対象」の欄に選び直すボタンが無い

正本の押し出しは「対象」「輪郭」の両方に「選び直す」が付いている。
いまは輪郭にしか無い。対象を替えたいとき、3D で選び直すしかない。

## FI-004 棚を `ShelvesFor` を通さずに出しているものが2つ残っている

`作業平面` と `表示` は、自分の命令から `show()+raise()` で出ている。
押し出しの棚が構造的に見えなかったのと同じ形である。
いまは試験にその2つを名前で列挙して例外扱いにしてあるので、
**3つ目を作ると門が鳴る**(`tests_v2/shelf_layout_tests.cpp`)。
作り直すなら、棚は全部 `ShelvesFor` から出す形にしてほしい。

## FI-005 Windows 95 テーマで、上の献立の文字が潰れている(オーナー報告)

オーナーの実機で「ファイル・作図・表示のあたりの文字が圧縮されて変」。
実機の絵で確かめた。`_claudeout/dpi/v2-win95-1920x1080.png` と、
同じ幅の既定テーマ `v2-guide-table-1920x1080-1.png` を並べると分かる。

測った値(献立の帯だけを切り出して、地の色と違う列を数えた)。

| | 既定テーマ | Windows 95 テーマ |
| --- | --- | --- |
| 献立の文字が占める幅 | x=11..689(678px) | x=4..636(632px) |
| 項目のあいだの空き(中央値) | 15px | 9px |
| 墨の切れ目の数 | 43 | 58 |

同じ字数が 46px 狭いところへ詰まっている。空きは6px 狭い。
切れ目が 58 と多いのは、字画が途切れているということである。
5倍に拡大すると「図」「操」が塊になって読めない。

コードの中で関係しそうなところ(**直していない。見ただけ**)。

- `Win95Style::Win95Font()` が `QFont::PreferBitmap | QFont::NoAntialias` を
  9pt の ＭＳ Ｐゴシックに掛けている。点の大きさに合う字形が無い拡大率だと
  近いものを引き伸ばすので、字が潰れる。滑らかにしないので漢字は特に潰れる。
- `PM_MenuBarItemSpacing` と `PM_MenuBarHMargin` がどちらも 0。
  項目のあいだに空きが無い。
- `CT_MenuBarItem` は高さ(19px)しか広げていない。横の余白を足していない。

## FI-006 同じテーマで、道具の帯が右端で途中から切れている

`v2-win95-1920x1080.png` の3段目。いちばん右が「作業平面を作ゃ」で切れている。
1920px あっても入りきらない。`»` も出ていないので、

## FI-007 人が見る状態・人がマウスで触る状態を、絵で確かめていない

FI-005 が今まで見つからなかった理由である。

いまの絵の撮り方(`_FIX_AND_BUILD.cmd` の [5])が撮っているのは
**置いただけの画面**である。撮っていないもの:

- 押している最中(pressed)・指している最中(hover)の見た目
- 献立を開いた状態(`QMenu` が出ているところ)
- 入力欄に焦点がある状態
- 実機の拡大率と実機のフォントで描いた状態
  (いまは `window.render()` なので、実機の画面とは別の道を通る)

**Windows 95 テーマは既定テーマとは別に撮る必要がある。**
いま win95 の絵は `v2-win95` の1枚だけで、献立も道具の帯も入っていない。
FI-005 はその1枚に写っていたのに、誰も拡大して見ていなかった。

提案(Claude は画面のコードを触らないので、作るのは Codex)。
撮った PNG を機械で測る門を足せば、人が拡大しなくても気づける。
測り方は上の表のとおりで、Claude が backend 側(`tools/` か `tests_v2/`)に
書くこともできる。要るなら `BACKEND_REQUIREMENT` で言ってください。
