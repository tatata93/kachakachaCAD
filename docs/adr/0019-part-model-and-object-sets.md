# ADR 0019: 部材近似モデルは派生レシピ、整理はセットで行う

## 状態

採用(2026-09-02)。`docs/surface-unfolding-spec.md` の実装方針。

## 決定

1. **部材近似モデル(PartModel)は板材を入力とする派生レシピとしてコア(model層)に持つ。**
   - 入力: 板材名+近似オプション(分割軸、自動/公差、最大部材数、最小部材幅、手動境界パラメータ)。
   - 計算: 板材の面を分割軸に沿った帯(部材)へ分割する。各部材の「1軸曲げ近似からのずれ」は、
     分割軸方向の等パラメータ曲線が部材内で弦からどれだけ離れるか(弦偏差)で見積もる。
   - 出力: 部材一覧(範囲・実幅・推定偏差・展開可否分類)と、部材境界の派生ワイヤ。
2. **派生物は既存オブジェクトとして具現化する。** 部材境界は `NamedWire`(`partModelSourceName` 付き)として
   生成する。既存の表示・選択・保存導線に乗せるためで、専用の描画経路は作らない。
   派生ワイヤは .kcd に保存せず、読み込み時にレシピから再生成する。
3. **セット(ObjectSet)を導入する。** 種類+名前でオブジェクトを束ね、状態
   (表示 / 参照のみ / 非表示)を持つ。部材近似モデルの派生物は自動セット「近似:<名前>」へ入る。
   ビューポートの表示判定(`ShouldDisplay`)はセット状態を参照する。
4. **型紙はio層で部材ごとに生成する。** 部材=板材範囲の制限なので、既存の
   `BuildPlateFlatPattern` を部材範囲の一時板材へ適用する。隣接部材の結合展開は範囲の合併で表す。
   折り線に山/谷方向(`foldDirection`)を追加する。

## 理由

- 面展開仕様の3段パイプライン(完成品→部材近似→型紙)の中間段を、既存の派生再生成の仕組み
  (投影ワイヤと同じ「レシピ+再構築」)に載せるのが最小で堅い。
- 展開エンジン(io層)は既にある。コアが必要とするのは「どこで区切るか」と「どれだけずれるか」の
  見積もりだけなので、model層に軽い弦偏差計算を持てば層違反なしに実装できる。
- 派生物を普通のワイヤとして出せば、UI・自動テスト・スナップがそのまま機能する。

## v1で実装しない(記録)

- 面を直接入力にする経路(v1は板材経由)。ワイヤ指定の手動境界(v1はパラメータ位置)。
- セット「参照のみ」のビューポート側の選択禁止(状態の保存と一覧表示のみ先行)。
- 部材ごとの派生「面」オブジェクト(v1は境界ワイヤのみ。面は型紙・組立プレビューで代替)。
