# シーン一覧から用紙へ配置する操作（2026-10-18）

基点633a2b1ce、WP-08内のUI変更。元CAD、幾何コア、KCIの保存形式は変更しない。

- 説明書モードの左側へ、作成済みシーンの縮小画像と名前を縦に並べる。
- 画像エディターでは一覧のシーンを選ぶと編集する。
- 用紙編集では一覧でシーンを選び、用紙をクリックすると3D参照の図を配置する。
- 左側に「シーンを編集」「用紙へ配置」を置き、どちらの画面からも移れるようにする。
- シーン追加・複製・名前変更・削除・Undo・別ファイル読込後も一覧を同期する。
- 取消やUndoで以前の配置予定が残らず、削除済みシーンを用紙へ置かない。
- 縮小画像は表示範囲のシーンを遅延生成して再利用し、一覧操作で全モデルを毎回描画しない。
- 説明書中はCADの一覧を隠し、他モードへ戻ると元の表示状態を戻す。

別経路の点検では、メニュー・帯・検索・ショートカット・モード往復を確認する。
作図ショートカットの重複と、表示操作で入力途中の道具が終了する問題を再現し、
必要な修正と回帰を同じUI所有範囲で行う。実行資源は主担当が管理し、調査担当は読み取りのみ。

重点回帰で実操作イベントと保存・Undo・参照UUIDを確認し、完成候補を固定してWindows全体ゲート、
開発版/配布版UI、通常起動を行う。結果・配布先は完了時に追記する。

## 別経路の不具合と回帰

- メニューと作図用QActionにL/C/V/M等が二重登録されていた。正式なメニューに登録を一本化し、
  作図帯もActivateCommand経由へ統一。重複登録数とQt QShortcutEvent配送、同じ道具の再選択後の
  入力・右ペイン保持を試験する。OSの物理キー操作を録画した試験とは区別する。
- 入力途中に全体表示/選択ズームを行うと、汎用ツールの対象入力が解除されていた。
  表示操作では構えを残し、未選択の表示操作は理由だけ示す。結合開始→未選択ズーム→1本選択→
  全体表示/選択ズーム→2本目選択→確定までを試験する。
- 左一覧のDeleteにはイベントフィルターとメニューの2経路があり、メニュー側が図の削除を行っていた。
  両方をフォーカスに従う削除へ揃えた。取消のSnapshot一致だけでは確認画面未表示を見逃すため、
  試験では確認画面に到達したことも必須にする。
- 一覧の新規・複製・改名・配置・同じシーンの再配置・削除・Undo/Redo・読込失敗・新規・再読込を確認。
  200シーンでも画面外の縮小画像は生成せず、縦拡大で新しく見えた行の画像も更新する。

最初の別経路試験はショートカットと全体表示の2件とも失敗し、修正後に成功した。
追加の左一覧Delete試験でも不足を検出し、修正後に確認画面・取消・削除・Undoが成功した。
失敗結果は out/instruction-browser-20261018 に残し、成功結果に読み替えない。
