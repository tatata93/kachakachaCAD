# kachakachaCAD 現状説明(2026-09-14 時点)

これは **引き継ぎ用の説明書** である。別の AI が途中から入っても、
いま何が終わっていて、何が残っていて、どう確かめるかが分かるように書く。

---

## 1. このプロジェクトは何か

鉄道模型を **プラ板と紙から作るための CAD**(kachakachaCAD)。
C++20 / Qt 6.9.2 / OCCT 8.0.1 / CMake。いま作っているのは V2。
V1 は残してある(オーナー指示「v2 が満足いくものになるまで v1 は消すな」)。

いちばん大事な決まりは **「できないことを、できたことにしない」**。
断るときは、必ず理由番号(`EXT-001` のような診断コード)と日本語の一文を出す。
理由番号は `docs/v2/diagnostic-catalog.md` に全部登録してある。

## 2. 作業の仕組み(ここが独特なので先に読む)

### 2.1 3者で回している

| 誰 | 何を持つ |
| --- | --- |
| オーナー(人) | 仕様と優先順位を決める |
| Claude(私) | `src/` `tests_v2/` `tools/` `docs/v2/*.md` `docs/manual/*.md` を書く |
| Codex | 仕様・受入・レビュー。`docs/manual.html` `samples/` `README.md` `manual_tests.cpp` を持つ |

やり取りは **ファイルで** する。

- Claude → Codex: `AI_HANDOFF_STATE.md`(Claude だけが書く)
- Codex → Claude: `CODEX_REVIEW.md`(Codex だけが書く)

Codex のレビューは **REQUEST_ID 単位の追記専用**。過去の FAIL/PASS は書き換えない。
直したら `P1-EXTRUDE-R3` → `R4` のように **新しい REQUEST_ID** で出し直す。
どのレビューを処理したかは `AI_HANDOFF_STATE.md` の
`PROCESSED_CODEX_REVIEWS`(REQUEST_ID / REVIEWED_HEAD / ACTION / FIX_COMMIT / RESULT)に残す。

**読んだだけでは「処理済み」にしない。** 直して、build して、試験を通して、
commit して、PC で確かめて、再レビューを出すまで未解決として扱う。

### 2.2 雲と PC の2か所でビルドする

| 場所 | できること | できないこと |
| --- | --- | --- |
| 雲(この作業環境) | core のビルドと試験(いま 134 件)、Qt の当て木による型検査(69 ファイル) | **Qt も OCCT も無い。** 画面も立体も動かせない |
| PC(Windows / MSVC 2022) | 本物のビルド、CTest 141 件、アプリの自己試験 225 件、画面の写真 | |

雲から PC へは **git の束(bundle)** で渡す。GitHub へは雲から push できない
(proxy が 403。fetch は通る)。PC 側は `_WATCH.cmd` が `to-pc.bundle` を見張っていて、
置かれたら `_FIX_AND_BUILD.cmd` が fetch → ff-merge → configure → build → CTest →
画面の写真 → 自己試験 → push を回し、結果を `_claudeout/run.txt` に書く。
**1往復およそ 12〜14 分。**

PC の作業場は `codex/v2-ui-ux-overhaul` を checkout している。Codex がそこへ
`CODEX_REVIEW.md` の追記を commit するので、雲側はときどきその commit を
取り込まないと ff-merge が失敗する(実際2回失敗した)。

### 2.3 雲で捕まえられない間違いを、雲で捕まえる道を足した

往復が高い(12分)ので、**PC でしか出ない間違い**を雲で捕まえる門を増やしている。
これは今回いちばん効いた改善である。

| 門 | 何を捕まえるか | 使い方 |
| --- | --- | --- |
| `tools/qtstub/typecheck.sh` | Qt が無い環境で画面のコードの型検査 | `sh tools/qtstub/typecheck.sh . g++` |
| `tools/bounds-check.sh`(**今日足した**) | 並びの外読み。Windows の Debug は `vector subscript out of range` で止まるが、雲の Release + g++ は黙って素通りする | `sh tools/bounds-check.sh .` |
| `architecture_tests` の「画面の関数の中身がある」(**今日足した**) | 宣言だけ残して中身を消した関数。型検査も CMake も見ない。PC の link で初めて分かる | core の試験に入っている |
| `architecture_tests` の各種台帳照合 | 命令の一覧・診断コード・受入表・結線表の書き忘れ | 同上 |

**PC へ束を送る前に、この3つを全部通すこと。**

### 3.3 今日直した中身(Codex の指摘)

**P1-EXTRUDE-R3**

- **B1 入れ子の取りやめを外側が飲み込む。**
  「外側で A → 内側で B → 内側が取りやめ → 外側が閉じる」で A も B も残っていた。
  一度でも内側が取りやめたら印(`compoundSpoiled_`)を立て、いちばん外側で
  閉じるときにまとめて戻す。`Transaction::Commit()` は
  **「本当に残ったか」を返す**(`[[nodiscard]]`)。
- **B2 文書だけ戻って、覚えている立体・辺・場面が新しいまま残る。**
  文書を変えるところを `CommitExtrudeAtomically()` に閉じこめ、
  **どの道で抜けても** 呼ぶ側が `AdoptCurrentDocument()` + `RebuildKernelShapes()`
  を通すようにした。
- **B3 Windows の Debug が止まる。**
  `TrimCurve` が並びの外を読んでいた。押した場所が線の外(0〜1 の外、NaN)だと
  必ず起きる。先に断る(`GEO-E022`)。**雲側で再現して潰した。**

**Q1-Q5-R2**

- **B1 無い部材番号が最後の部材へ丸められる。**
  部材3枚のときに「999」と書くと、黙って3枚目の半径が変わっていた。丸めずに断る。
- **B2 「分けられます」と見せた相手と、実際に変える境目が別物。**
  `fabrication/BandPartition` を新しく作り、**見せる形と決めたあとに使う形を
  同じ1つの候補から** 作るようにした。書いたあとで枚数を突き合わせる。
- **B3** は R3 B3 と同じ `TrimCurve`。

### 3.4 今日の副産物(Codex 指摘の外で見つけて直したもの)

- **HO 見本の面が一度も作られていなかった。**
  面の作り方が持つ「鎖」の指し先は **1本のワイヤー** であって曲線1本ではない。
  曲線の数だけ指し先を並べていたので `UI-R006` で断られ続けていた。
  V1 の見本(`RailwayNoseSample.cpp`)は最初から正しく書いてある。
  これを捕まえる core 試験を足した(雲で止まる)。
- **面の作り方の当たり外れ。** PC で全部試させて答えを出した。
  - 断面を通すロフト(`ThruSections`): **通る**
  - 案内付きロフト(`MakePipeShell`): 断面から 0.19mm 外れて断られる
  - 曲線網(`MakeFilling`): そもそも面が張れない
  見本は断面を通すロフトに寄せ、**使われない案内線は全部消した**(§44)。
- **押し出しが選択をそのまま輪郭にしていた。**
  足す・引くでは立体も一緒に選ぶので、立体まで輪郭に数えられ `EXT-001` で
  断られていた。読み取り(`plan.profiles`)が輪郭と決めたものだけを使う。
- **選んだ輪郭の平面で押すようにした。**
  作業平面の法線で押していたので、別の平面に引いた輪郭(HO の窓など)を
  選ぶと `EXT-007` で断られていた。

## 4. 残っている宿題

### 4.1 いま確認中(PC 待ち)

- `7610782` の2件(EXT-001 / EXT-007)が消えたかどうか。
- 消えたら **`P1-EXTRUDE-R4`** と **`Q1-Q5-R3`** を、その commit を BASE/HEAD に
  固定して `AI_HANDOFF_STATE.md` へ出す。HEAD は必ず Claude が固定する
  (Codex に「最新 commit から適当に選ばせる」運用にしない)。

### 4.2 Codex に判断を委ねたもの(`AI_HANDOFF_STATE.md` に CODEX_REVIEW_REQUIRED)

1. **ずれの許容が、近似で作る面を事実上禁じている。**
   `OcctGuideSurface` の「作ったものを測り、通っていなければ捨てる」検査は、
   許容が `max(modelLinearMm * 10, 1e-4)` = **0.0001mm**。
   案内付きロフトも曲線網も作りからして近似なので、どんな形でも断られる。
   「命令の一覧にはあるが実際には使えない」状態。直し方の案を3つ書いて渡した。
2. **形を作る層へ手を入れた。** `BuildGuidedLoft` の `WithCorrection` を
   真 → 偽 にした(断面を勝手に回されると 8.4mm ずれるため)。ここは GUARDED。

### 4.3 人の判断が要るもの(HUMAN_DECISION_REQUIRED)

1. **面を分類する方式(V2方式)の分け方を文書に持てない。**
   面の集合を保存することになり、「面番号を保存してはならない」
   (`architecture-and-data.md §6`)とぶつかる。
   帯近似(V1方式)のほうは **今日解決した**(境目のパラメータなので保存できる)。
2. **複数の面を1枚の部材にまとめる道が無い。**
   いまの部材は1枚の格子で出来ていて、別々の面の格子を繋ぐ道が無い。
   部材の持ち方そのものの作り直しになる(GUARDED)。

## 5. 触るときに知っておくこと

### 5.1 ビルドと試験

```
# core(雲)
cmake -S . -B build-core && cmake --build build-core --parallel 8
cd build-core && ctest -E qt_stub          # 134 件

# 画面の型検査(雲)
sh tools/qtstub/typecheck.sh . g++         # 69 ファイル

# 並びの外読み(雲。PC へ送る前に必ず)
sh tools/bounds-check.sh .                 # 134 件
```

**ctest は作り直さない。** 必ず先に `cmake --build` する。

### 5.2 やってはいけないこと(オーナー指示)

- 未コミットの作業を勝手に stash する / `reset --hard` する / 無断で rebase する
- 他の AI の枝を上書きする
- 落ちる試験を skip する / 試験を消して PASS にする
- Codex の Blocking を無視する

### 5.3 commit の書き方

末尾に必ず付ける:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_01PhuCKP4297isBKknmQumJ3
```

本文は **何を直したかではなく、なぜそうなっていたか** を書く。
コードの注釈も同じで、「どう動くか」ではなく「なぜそう決めたか」を残す。

### 5.4 試験の書き方の落とし穴

- `KACHA_V2_TEST(suite, name)` の name は **識別子として正しい文字だけ**
  (空白・`、`・`・` は使えない)
- `RequireEqual` は文字列どうししか比べられない。数は `Require(a == b, ...)`
- OCCT が入ると `Square` のような **大域の関数と名前がぶつかる**。
  無名名前空間の中身も大域の一員なので、MSVC が「どちらとも取れる」で止まる。
  雲では OCCT が無いので出ない。道具の名前は少し長めにする。

## 6. いま動いている機能(オーナー指示 Q1〜Q5)

| # | 中身 | 状態 |
| --- | --- | --- |
| Q1 | 選択に正対(作業平面 / 立体の面 / 曲面)。向き+注視点+中央+大きさを1操作で | 実装済み。複数選んだときの決まりも決めた(**向きは最初の1つ、収まりは全部**) |

| Q3 | HO(1/80・16.5mm)流線形前頭部の総合試験モデル | 作業平面 → 断面 → 面 → 押し出し試験 → 近似 まで作り方として持つ。完成形は書き込んでいない |
| Q4 | 総合試験。何も無い文書から本番の指示だけで、面 → 近似 → 曲げ → 線と面の出力まで | 実装済み(`V2SelfTestApproxFlow`) |
| Q5 | 部材ごとの半径と AUTO/LOCK、部材の分割と統合、展開の基準にする辺 | 全部実装済み。半径は文書が持ち、**実際に形を変える** |

固定値の近似候補、単純な CG モーフ、UI だけの AUTO/LOCK など)は、
