# 自宅PCから学校PCで開発する

2026-11-27のオーナー指示に基づく初回設定。通常の運用は
[自宅・学校PCの開発運用](../ai/home-school-workflow.md)を使う。

## 現在の設定状況

| 項目 | 状態 |
| --- | --- |
| 自宅PC | 指示・確認・統合の担当 |
| 学校PC | Windows、帰宅後も稼働可能とのオーナー回答 |
| 接続先の識別 | 遠隔チャットのhost IDを取得済み。個別のPC名・IDはローカル記録で管理 |
| 自宅からの遠隔接続 | 学校側チャットの履歴取得と開始指示の送信が成功 |
| 学校PCのCADプロジェクト | clone済み。アプリの保存済みプロジェクトへの登録は未確認 |
| 学校PCのビルド | OCCT導入・開発版ビルドと、点選択・作業面の重点試験14例の成功を学校側が報告 |
| 学校PCの画面操作 | 公開版で実クリック作図・選択・Undo/Redo・保存再読込を確認。開発版の実操作受入は別に記録 |
| 学校PCの継続実行 | 学校側の自律実行を指示済み。環境整備後のWP-08操作不具合の一括担当を送信。成果の受入は未完了 |

学校側の初回検証記録は `codex/school/setup` の64b2c929としてpush済み。
ER2のZIP・内部6ファイルのハッシュ一致と作業コピー作成を学校側が報告した。
現在の優先対象は [ER2継続開発のIssue #3](https://github.com/tatata93/kachakachaCAD/issues/3)。

準備用ブランチは `codex/home-school-development`。
進行中のCAD検証・原本・他担当の作業は移動、取り込み、破棄しない。

## 1. PC同士を接続する

1. 両PCのアプリを同じChatGPTアカウントとワークスペースで使う。
2. 学校PCで設定 → 接続 →「このPCを操作」を有効にする。
3. 自宅PCで設定 → 接続 →「他のデバイスを操作」から学校PCを追加する。
4. 自宅で学校PCを選び、そのPCのプロジェクトを開けることを確認する。

接続先を選べてもプロジェクトが一覧に出ない場合は、学校側のcloneをアプリのプロジェクトへ追加する。
自宅の主担当に渡すのは接続されたプロジェクトの情報であり、PCの表示名をhost IDへ代用しない。

名称や提供状況はアプリ版・アカウントにより異なる。
認証と接続許可はオーナーが画面で行い、パスワード・トークン・認証ファイルをチャットやGitへ渡さない。
別PCから同じアカウントでログインしただけでは、同じ作業フォルダーを操作できた証拠にはならない。

学校PCはオンラインでアプリが動いている必要がある。
WindowsのComputer Useを行う時間は、学校PCのデスクトップを使用可能な状態にして専有する。
接続切れ・スリープ・画面ロック中の操作を成功扱いしない。

公式資料: [Remote connections](https://learn.chatgpt.com/docs/remote-connections)

## 2. 学校PCのプロジェクトを用意する

学校PCのCodexへ[学校PCの開始指示](../ai/prompts/school-pc-start.txt)を渡す。
既存のcloneがあれば所有者と未コミット変更を確認して使い、なければGitHubからcloneする。

```text
https://github.com/tatata93/kachakachaCAD.git
```

既存の変更を上書きするためのcloneやresetをしない。
開発基点は現在の開発ブランチ `codex/v2-wp01-build-scaffold` とし、mainや古い配布版から推測しない。
準備文書は `codex/home-school-development` にある。最新版の取得先を確認して読む。
学校PCのcloneをアプリのプロジェクトとして登録し、自宅から同じリポジトリを識別できるか確かめる。

初回確認時、学校側はmainをcloneしていた。mainのd3893fa64は自宅の検証中ブランチの祖先で、
887コミットの差があった。作業中のmainや依存ビルドを破棄せず、必要なら分離worktreeで
検証中ブランチを取得する。mainの最新と、現在の開発版の最新を混同しない。

GitHub認証は学校PCで通常のログインを行う。自宅PCの認証情報を転用しない。
必要な開発環境は[Windows環境](../setup-windows.md)と既存CMakeプリセットに合わせる。
依存の場所はそのPCの環境変数かGit管理外の `local.cmake` に記録する。

## 3. 初回の受入確認

| 確認 | 証拠 |
| --- | --- |
| 接続先 | 自宅から取得したhost IDと表示名、学校側が報告した実行PCとの一致 |
| プロジェクト | originのURL、ブランチ、HEAD、所有不明の変更を触っていない記録 |
| 開発環境 | Git/CMake/Python/MSVC/Qt/OCCTの実在、doctorと構成結果 |
| GitHub | 学校側から自分の作業ブランチをpushできること |
| 実画面 | CADの画像取得、実クリック、無題文書で2点の線を作る、選択、Undo/Redo |
| 保存 | 試験用文書を保存・再読込できること。オーナーの原本で試さない |
| 自宅への結果返却 | コミットと検証記録を自宅から参照できること |

GUI自己試験の成功とComputer Useの成功は別々に記録する。
画像取得やクリックが失敗したら、そのエラーを残して画面操作を未確認とする。
数値座標の注入やファイルの直接生成を、実クリックで模型を作れた証拠にしない。

## 4. 継続開発へ切り替える

上の確認後、学校PCのチャットを継続開発の実行先にする。
自宅は修正依頼、結果確認、単一の統合担当を持つ。
手動報告と継続改善は同じ[依頼記録](../ai/templates/cad-work-item.md)で管理する。

自宅が操作を逐次中継せず、学校PCのCodexが自分で調査・修正・ビルド・CAD操作まで行う。
初回環境確認の後に選択・作図面・ワイヤ編集・ツール遷移の不具合を1件ずつ扱う一括指示を送信した。
自宅の製品ソースは検証用に凍結し、学校側の担当範囲を同時に実装しない。

オーナーの追加指示により、一般的な巡回より[ER2の継続開発](../ai/handoffs/er2-20261127.md)を優先する。
原本3版と再開メモは未公開draft releaseで受け渡し、受領時のハッシュ照合を学校側で行う。

この文書の追加だけでは、遠隔接続、継続チャット、定期実行の登録は行われない。
接続先と動作を確認してから、学校PC側の実行を有効にする。
自宅PCへ代わりの定期実行を作らない。旧レビュー常駐も再開しない。
