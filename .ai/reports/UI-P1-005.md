# Implementation

Smallest plan: put every rule of the rectangle in core, and let the viewport only arm/extend/finish the gesture and draw it.

**core (`app/Selection`)** — new, Qt/OCCT-free:
- `ScreenBox` (normalized, `Contains`), `BoxSelectionKind{Contained, Crossing}`, `BoxSelection`.
- `MakeBoxSelection(start, end)` — direction decides the kind from the horizontal sense only (`end.x >= start.x` → `Contained`); vertical sense is normalized away.
- `BoxSelectionIsMeaningful` / `BoxSelectionMinimumDragPx()` — the 5 logical px gate, deliberately a separate constant from `GrabToMove`'s 4 px slop.
- `BoxTouchesSegment` — Liang–Barsky, so a line that spans a thin rectangle without any sample inside still counts as crossing.
- `BoxReach` + `AccumulateBoxReach/Curve/Point` and `BoxReach::Taken(kind)` — one counting rule reused by curves, drawing points and (from the UI) mesh edges. `fullyInside` is falsified by any unprojectable point, so a partly off-camera object is never reported as "fully contained".
- `CollectBoxPickCandidates` — accumulates **per entity** and returns `SelectionElementKind::Object` candidates with no segment id, because §4.2 selects 対象. Reuses `PickableOffPlaneCurve` so a dimmed-and-unpickable line is not box-pickable either.
- `ApplyBoxSelection` — `Replace` rebuilds from the candidates (looping `ApplySelection` would leave only the last one); `Add/Toggle/Subtract` match **per entity** so a wire that already has one segment selected does not end up counted twice; duplicate candidates are collapsed first.

**viewport** — `BeginBoxSelect / DragBoxSelect / ReleaseBoxSelect / CancelBoxSelect`, plus `BoxSelecting / BoxSelectRect / BoxSelectKind` for drawing and tests. A left press in the Select tool still selects one candidate immediately (no regression to click feel) and *also* arms the rectangle, remembering the selection as it was **before** the press; the release re-applies from that base, so a click and a rectangle never mix. Release under 5 px does nothing. `Ctrl` is read through one new shared helper `SelectionModeFor`, now used by `SelectAt` too. Shapes are gathered in `CollectBoxShapeCandidates` from `ShapeView::mesh.edges` using the same core accumulator. The rubber band is drawn solid for containment and dashed for crossing, and only once the 5 px gate is passed. Right-press is ignored while rubber-banding, `Esc` cancels the band only, and `PruneSelection` drops a band left over from a document change.

## 5. エラー処理・退行

- 投影できない点は `fullyInside` を落とすので、カメラ裏に伸びた対象が「完全包含」にならない。退化線分（始点=終点）は `BoxTouchesSegment` の分母 0 経路で正しく外へ弾かれる。
- 状態分離は守られている。`boxSelect_` は Hover / Selection / `cycle_` と別に持ち、引いている間は Hover とスナップを探さない。`PruneSelection` が引きかけの矩形を捨てるので、文書変更後に消えた物体を含む「押した時点の選択」を復元してしまう穴がない。`Esc` は矩形だけを取り消し、core の `EscapeAction` 段には触っていない。
- 押下時の 1 件選択（クリック感）は維持され、離すときは押下前の選択から当て直すので、クリックと矩形が混ざらない。右押しは矩形中に無視、`PickPending()` 中は矩形を構えない。
- `shapesVisible` はクリック・矩形の両方で尊重。`pickMeshes_` は `shapeViews_` の 1:1 写しなので、クリックで拾えない形が矩形だけで拾えることはない。`SceneBuilder` が非表示 Entity を除くため、隠した物体は矩形でも選ばれない。

## 6. 残る注意点（いずれも今回の差し戻し理由ではない）

1. `mouseMoveEvent` は `boxSelect_` を `panning_` より先に見るが、`mousePressEvent` の中ボタンには右ボタンのような矩形中ガードが無い。左を押したまま中ボタンを押すとパンは効かず、矩形が続く。挙動としては妥当だが、右ボタンとの対称性は次に触るときに揃えたい。
2. 完全包含の判定は曲線の標本弦で行うため、許容差の範囲で枠外へ膨らむ円弧が「完全包含」になりうる。クリック側の判定と同じ標本化なので整合はしている。
3. 矩形は Object 参照を作るので、矩形で選んだ線を Ctrl+クリックしても（Edge 参照と別物のため）外れず、もう 1 件増える。ただしこれは `SelectAllOfKind` や `entityIds` 由来の Entity 単位参照でも以前から起きる既存挙動で、本差分が作った欠陥ではない。

5. 塗った形は稜線でのみ判定するため、面の内側だけを囲む矩形では部品を選べない。作業平面は矩形でもクリックでも拾えない（新たな欠落ではない）。
