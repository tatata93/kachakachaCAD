# 提案: 製作近似の残りをつなぐ(Codex 判断待ち)

オーナー指示(2026-09-13)の項目12「面の解析 → 3次元曲面の自動近似 → 板材化 →
展開 → 逃がし切り・分割 → 治具」のうち、Claude が触れないところの提案である。

項目11(GUARDED)により、保存の形・文書の持ち物・Command の作られ方の
根っこは、こちらから一方的に変えない。ここに案と影響を書いて判断を仰ぐ。

## いま繋がった分(判断不要、実装済み)

| もの | やったこと | 保存の形 |
| --- | --- | --- |
| `fabrication/CurvatureAnalysis.h` | 展開を断るとき、どんな曲がり方かと一番ひどい場所まで言う | 変えていない |
| `fabrication/ReliefCut.h` | 引いた切れ目を型紙にする前に §7.5 で検査する | 変えていない |

どちらも診断の言葉が増えただけで、文書にも `.kcd2` にも新しい持ち物は増えていない。

## 判断が要るもの

### 1. 切れ目の上限を画面から変えられるようにする(小、GUARDED の端)

いまの検査は `FabricationSettings` の既定値を使っている。
深さは部材幅の 55% まで、先端から縁まで 0.5mm。**画面から変えられない。**

紙とプラ板と真鍮では、残してよい幅が違う。0.5mm は 0.3mm 厚のプラ板の値で、
薄い紙ならもっと狭くてよいし、真鍮なら足りない。

- **案:** `CreateFabricationModelDefinition` に
  `double maximumReliefDepthRatio = 0.55;` と `double minimumLigamentMm = 0.5;` を足す。
  製作の棚に2つの欄を出す。
- **影響:** `.kcd2` に鍵が2つ増える。古い文書は既定値で読める(既存の鍵と同じ扱い)。
  Undo/Redo は定義の差し替えなので既存の道に乗る。
- **判断してほしいこと:** 定義に持たせるのか、文書ごとの設定
  (`settings` のほう)に持たせるのか。材料は部材ごとに変わりうるので、
  本当は部材ごとかもしれない。そこは決めきれていない。

### 2. 部材の分け方(`fabrication/PanelStrategy.h`)(大)

**いま V2 方式は、展開できない面が1枚でもあると、そこで全部を断る。**
「1枚では無理だが、3枚に分ければできる」と言えない。分けることもできない。

`PanelStrategy` は書けていて試験もある。4通り(1枚 / 少数 / 全部ばらす / 混合)を
作り比べられる。繋がっていないのは、**入力の片方が無いから** である。

`BuildPanelPartition` は `PanelCandidate`(面ごとの分類・偏差・面積)と
`PanelAdjacency`(どの面とどの面が、どれだけの長さの辺を、何度の角で共有しているか)を
要る。前者は `CurvatureAnalysis` から作れる。**後者を作る道が無い。**

隣り合わせは形の話なので、カーネル(OCCT)が共有辺を数えるしかない。

- **案:** `src/next_occt` に `OcctFaceAdjacency.h` を足す。
  `TopExp::MapShapesAndAncestors` で辺 → 面の対応を作り、
  2つの面に共有される辺ごとに、長さと二面角を返す。
  返すのは番号と数だけ(`PanelAdjacency` そのもの)で、OCCT の型は core へ出さない。
- **影響:** カーネルの新しいヘッダが1つ。雲では構文検査すらできない
  (`core-ui-wiring.md` の最後に書いてあるとおり)ので、
  **小さく刻んで1往復ずつ PC で確かめる** 必要がある。
  文書の持ち物は増えない(分け方は近似の結果であって、定義ではない)。
  ただし「どの分け方を選んだか」は定義に要る(下の3と同じ話)。
- **判断してほしいこと:** この順で進めてよいか。
  先に `PanelStrategy` を「報告だけ」で繋ぐ手もある
  (断るときに「1枚では無理。3枚に分ければできます」とだけ言い、分けはしない)。
  それなら隣り合わせが要らない場合もあるが、**面が1枚のときしか言えない** ので、
  半端になる。

### 3. どの分け方を選んだかを覚える(中、GUARDED)

2を入れるなら、定義に `int strategy` が要る。
`FabricationStrategy` の 0〜3(1枚 / 少数 / 全部ばらす / 混合)。

- **影響:** `.kcd2` に鍵が1つ。古い文書は「少数」(既定)で読める。
  近似のやり直しの入口が1つ増えるので、製作の棚に選ぶ欄が要る。
- **判断してほしいこと:** 既定を「少数」にしてよいか。
  V1 は何をしていたか(V1 に対応する概念があるなら、そちらに寄せたい)。

### 4. 役割の手動割り当て(`fabrication/ManualRole.h`)(中、GUARDED)

「ここで必ず分ける」「ここはつないだままにする」を人が指定する仕組み。
`PanelAdjacency` の `forcedBoundary` / `keepTogether` がその受け口である。

2と3が入らないと置き場所が無いので、**2・3のあとにする** 。

### 5. 部材をまたぐ開口(`fabrication/OpeningClip.h`)(中)

V1 方式(帯)のまたぐ窓は繋いである(`app/FabricationOpenings`)。
V2 方式の平らな部材どうしをまたぐ窓が残っている。これも2のあと。

### 6. 曲げ状態の固定(`fabrication/FreezeMaterialize.h`)(大、GUARDED)

固めたものを文書のものに変える。文書へ物を作るので、まるごと GUARDED である。
V1 方式の `FreezeOutput` は繋いであり、V2 方式の `FreezeAssemblyState` が残っている。

## Claude の見立て

作る人の役に立つ順で並べると **1 → 2 → 3 → 5 → 4 → 6** である。

1は小さいのに効く。いまは検査の値が隠れていて、
紙とプラ板で同じ 0.5mm が使われている。

2が一番大きい山で、ここが通らないと V2 方式は
「平らな部品と、たまたま展開できる曲面」しか扱えないままになる。
オーナーの言う「3次元曲面の自動近似」は、実質ここのことだと読んでいる。
