# 操作全般の性能改善（2026-10-22）

対象はWP-08のUI境界。基点 `695a9ecf5`、実装 `e8249a446`。
幾何カーネル、保存形式、曲線の標本精度、三角形数、近似許容誤差を変更していない。
全処理が一定時間以下になったという意味での完了ではない。今回確認した範囲と残る待ち時間を区別する。

## 原因と修正

| 待ち時間の原因 | 修正 |
| --- | --- |
| 毎フレーム、GPUの絵をCPU画像へ読み戻して再び画面へコピー | WindowsではQOpenGLWidget子へ直接描画。入力・ピック・CAD状態は親Viewportに維持 |
| ワイヤーの表示チェックでも、無関係な全形状の表示メッシュを更新 | ワイヤー・点・作業平面の切替では形状メッシュ更新を省く。グループ・面・立体の変更では更新を残す |
| キャッシュのメッシュを複数回コピーして保持し直す | mapのnodeを移し、形状の同一性と非表示メッシュを保持 |
| 形状ごとの稜線復元が全Sceneを繰り返し走査 | Entity UUIDごとの旧曲線索引を作り、既存SegmentIdを維持 |
| 一覧チェックや輪郭検出で、行・曲線ごとに文書を線形探索 | その更新内だけのEntity/Feature/Group UUID索引を使用。文書をまたぐポインターのキャッシュは作らない |
| 読み込みとUndo後の稜線・Scene更新が重複 | Adopt済みの更新を再度呼ばない |
| 選択通知でFactsを複数回生成し、ボタン可否確認で押し出しの幾何プレビューまで計算 | 同期通知内でFactsを共有。正確な押し出し計画はツール開始・プレビュー・確定時に残す |
| 平面一覧が不変でもコンボをclear/addし、入力・下見を刺激 | UUIDと表示名が同じなら一覧を作り直さず、現在の平面だけ同期 |
| 読み込み転送結果が値返却後に大きくコピーされる | UI内の一時転送データをunique_ptrで所有し、読み取った結果をmove |
| 同じ文書を保存しても毎回BRepとメッシュをシリアライズ | 文書バイト列・実行ファイル/依存DLL・キャッシュ内容が検証できる場合は既存キャッシュを再利用 |

GPU非対応、ソフトウェア描画、offscreenでは既存経路を維持する。
GL子の初期化・共有・描画失敗時も既存経路へ戻す。ユーザーアプリを終了させない。
QWidgetのrender/grab時には明示的なGL paint deviceを使い、古いFBOで撮影画像を上書きする問題も修正した。
通常描画にはglFinishを入れず、明示的な性能試験だけでGPU完了を待つ。

## 同じPCでの測定

Windows、Release、Qt 6.9.2、GTX 1060 6GB。ビルド・他のGUI試験と重ねず逐次実行した。
実モデルの原本SHA-256を前後照合した。単発のセッション比較であり、統計的な母集団や他PCの保証ではない。

### 左ペイン・読み込み

基準は直前の検証済み配布exe、改善後は実装候補。新しいTEMP・文書キャッシュを毎実行で分離。
選択10回、チェック50回をQtマウスイベントとチェック操作で確認し、行・スクロール位置・非表示状態・原本不変を検査した。
OSへのマウス入力注入ではない。

| 操作 | 115投影：前→後 | 大規模モデル：前→後 |
| --- | --- | --- |
| 選択の中央値 | 13.61→15.45 ms | 19.39→16.25 ms |
| 表示チェックの中央値 | 12.43→16.70 ms | 343.18→73.26 ms |
| 表示チェックの最大 | 18.63→23.33 ms | 452.57→79.23 ms |
| キャッシュなし読み込み | 4.469→4.563 s | 23.600→22.710 s |
| キャッシュあり読み込み | 0.753→0.819 s | 7.524→7.169 s |

大規模モデルの表示切替は約79%短縮。小さいモデルの数msの増加も記録した。
読み込みは大きな短縮には至っていない。BRep復元・メッシュ準備・転送が残る。
保存・Undo・各形状操作は回帰試験の対象だが、すべての操作で独立した速度比較を行ったとは扱わない。

### 視点操作

同じ候補exeで旧経路と新経路を切り替え、その他の変更を固定した比較。
2560×1440ウィンドウ、倍率100%、各条件4回のウォームアップ後64フレーム。
グリッドなし・主線・副線・ほぼ真横、回転・平行移動を別々に測定。
下表は副線を出した回転の描画処理。GPU処理の完了まで含む。

| モデル | 描画中央値：旧→新 | p95：旧→新 |
| --- | --- | --- |
| 空の作図 | 8.27→2.30 ms | 9.54→3.10 ms |
| 115投影 | 9.44→3.02 ms | 11.07→3.98 ms |
| 大規模モデル | 11.43→5.36 ms | 12.94→6.15 ms |

新経路は各条件で68回以上の実描画を確認し、通常フレームのアプリ側画像読み戻しは0回。
撮影時の読み戻しは必要なので別扱い。画面提示までの全体時間にはQtの合成・垂直同期が入り、
中央値は約16.7msとなる。描画処理時間とモニターの実提示FPSを混同しない。
p95や最大値のスパイクはCSVにも残している。全条件で常時60fpsを保証する結果ではない。

## 検証と不採用の途中状態

直接描画の初版は、撮影時のグリッド・選択色・合成画像の3回帰ケースで失敗した。
QPainterの撮影先とGLのFBOが混在することを修正し、同じ試験を通した。
最初の性能試験も「実描画回数不足」を失敗として検出した。Qtの合成イベントとGPU完了まで
待つ方式に変更し、依頼だけ速い状態を速度改善と誤認しないようにした。
失敗ログを消したり、比較する画素条件を緩めたりしていない。

新規の回帰試験は、ワイヤー表示と面の同一性、native稜線ID、Undo/Redo・保存再読込、
画面更新と撮影、リサイズ、アイドル時に連続描画しないこと。
Windowsの関連37ケースと、倍率150%の重点5ケースが成功した。
最終候補ではWindowsの実画面552ケースを全件実行し、失敗0（859.58秒）。
ソフトウェア描画の重点5ケースも失敗0。正式ゲート・配布版の最終結果は下に追記する。
