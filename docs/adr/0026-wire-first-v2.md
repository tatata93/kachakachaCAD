# ADR 0026: Wire-first V2へ段階的に置き換える

## 状態

採用(2026-09-08)。V2仕様はcommit `25d9982` で凍結済み。

## 背景

現行版は `Wire`、`Surface`、`Plate`、`Body`、`PartModel` を別の利用者向け種類として増やしてきた。
内部構造がそのままモデル一覧と操作手順へ現れ、同じ形に対して「面を選ぶのか、板材を選ぶのか、
実体を選ぶのか」を利用者へ判断させている。また、表示名による参照、巨大なUIクラス、派生物の
具現化と再生成の混在により、機能追加のたびに別経路が増えやすい。

一方で、曲線計算、作業平面、数式入力、計測、部材近似の試験資産、OCCTによる検査と出力、
Windowsビルドと配布処理には再利用価値がある。全コードを捨てることも、現行データモデルへ
さらに機能を継ぎ足すことも適切ではない。

## 決定

1. 利用者の主編集対象をワイヤーと部品へ統一する。
2. 曲面生成結果は `形状ガイド` と呼び、部品そのものではなく参照・近似・投影に使う。
3. 物理形状は1つの連結閉ソリッドである `部品` だけに統一する。治具も役割属性を持つ部品である。
4. 板厚や材料は部品または製作モデルの属性にする。`板材` を独立した利用者向けオブジェクトにしない。
5. UUID参照、Feature DAG、トランザクション、構造化JSON保存を新設する。旧 `.kcd` 互換は持たない。
6. V2は現行版と並行して構築し、受入試験を通すまでは現行実装を削除しない。
7. 受入後に旧 `Project`、`ProjectScript`、`Surface/Plate` UI、名前参照、暫定スタブを削除する。
8. 幾何コアとQt/OCCT境界は分離する。UI内へ幾何処理を実装しない。

## 代替案

### 現行構造をそのまま整理する

UI上だけ面と板材を統合しても、保存形式と依存関係には二重性が残り、新しい押し出し、ソリッド化、
近似生成が旧種類ごとに分岐するため却下した。

### 完全に別リポジトリでゼロから作る

検証済みの幾何処理、出力、テスト、ビルド、配布知識を失い、同じ不具合を再発させるため却下した。

### 現行版を先に削除してからV2を作る

長期間起動可能な版を失い、段階的な比較と回帰確認ができないため却下した。

## 結果

- 移行期間だけ旧実装とV2実装が共存する。
- 共存は期限付きであり、受入後に旧実装を削除する作業パッケージを必須とする。
- V2へ移植したアルゴリズムは旧クラスを直接参照せず、V2の値型と契約へ適合させる。
- 旧形式の読込要求が後から出た場合は、本体へ互換分岐を戻さず、独立した一回限りの変換ツールとして別ADRで扱う。
