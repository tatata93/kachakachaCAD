# ADR 0020: UIの再設計 — 右パネルの脱スクロールとワークフロー主導の再編

## 状態

採用(2026-09-01)。段階実施。オーナー指示:
「現状のuiはとにかく使いにくい。特に右ウインドウがいちいちスクロールしたり、
作図に使う項目が分かれていたりする。inventorやソリッドワークス、fusion360、
JWCADなど調べてuiや操作系を一新しろ」

## 現状の問題

- 右ドック(幅380〜460px)に10タブ(作図/作業平面/数値入力/編集/加工/面/出力/表示/情報/部材)。
  各タブは縦一列のフォームで、特に「出力」「作図」「面」はQScrollAreaのスクロールが常時必要。
- 作図に使う項目が「作図」「数値入力」「編集」「加工」の4タブに分散し、行き来が多い。
- どの操作がどのタブにあるか覚えるまで探し回る(コマンド検索がない)。

## 参考にした市販CADの構造

- **Inventor / SolidWorks / Fusion 360**: 上部リボン(ワークフロー別タブ+コマンド群)、
  左ブラウザ(モデルツリー)、コマンド実行中だけ出る小さなパラメータダイアログ/パネル。
  「常設の巨大な右パネル」は持たない。スケッチ環境では投影ジオメトリと推測スナップ
  (延長線・平行・直交の点線ガイド)が作図の主力。
- **JWCAD**: 常設の両脇ツールバー+クロックメニュー。コマンドは浅く、値入力は
  コントロールバー(上部一行)で完結する。

## 決定

1. **段階的に移行する(ビッグバン禁止)。** セルフテストとマニュアル画像がタブ構成に
   依存しているため、動くものを保ちながら1段ずつ変える。各段階でセルフテストを更新する。
2. **第1段: 折りたたみセクション化と情報密度の改善(タブ構成は不変)。**
   - 折りたたみ可能なセクション部品(見出しクリックで開閉、状態は保存)を導入し、
     「出力」「作図」「面」「加工」の長いフォームを役割ごとのセクションへ分ける。
     既定では主要セクションだけ開く。これで常時スクロールを解消する。
   - 右ドックの最大幅を560pxへ広げ、ボタン列は2列グリッド化できるところから詰める。
3. **第2段: タブの統合(10→5)。** 作図系の分散を解消する。
   - 「スケッチ」= 作図+数値入力+編集+加工(セクションで区分け)
   - 「立体」= 面+板材(分割・治具含む)
   - 「部材」= 部材近似+型紙+曲げ出力(現部材タブ)
   - 「出力」= 1:1図面+PDF/SVG/DXF+STL/STEP
   - 「表示・検査」= 表示+情報
   ワークフローボタン(1平面 2作図 3面板 4出力)はタブ統合後の5タブと一対一にする。
   セルフテストのタブ番号・マニュアル画像状態を同時に更新する。
4. **第3段: コンテキスト化。** コマンド実行中(線を引く・面取りする等)は、そのコマンドの
   パラメータだけを小さなフローティングパネル(またはドック上部)に出し、常設パネルは
   ブラウザ(モデルツリー+セット)中心へ寄せる。ビューポート右クリックに
   よく使うコマンドのメニューを追加する。
5. **操作系はスナップ・推測を主力にする。** 延長線・投影点の推測スナップ(実装済み)に加え、
   平行・直交・中点の推測、コマンド検索(Ctrl+K)を第3段までに足す。
6. **moc不使用・名前文字列参照などの既存方針は変えない(ADR 0018 踏襲)。**

## 理由

- スクロールの主因は「1タブ=1本の長いフォーム」。タブを保ったままセクション開閉を
  入れるのが、テスト資産を壊さず最速で効く。
- タブ統合は自己テスト・ドキュメント(マニュアル画像)への影響が大きいので、
  セクション化で構造を整えてから一括で行う方が差分が小さい。
- 市販CADの本質は「常設UIを薄くし、文脈で必要なものだけ出す」。第3段はそれに寄せる。

## 検証方法

- 各段階で: linux-core 全テスト → Windows実機ビルド → セルフテスト(qt_cad_smoke)
  → 手動スクリーンショット states の目視(オーナー受入)。
- 第1段の受入基準: 1920x1080・既定ウィンドウで「作図」「出力」タブの主要操作
  (線を引く、型紙を出す、SVG/STL保存)がスクロールなしで届くこと。
