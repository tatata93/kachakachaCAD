# Remaining issues

1. **Stronger snap for tool-suited candidates is not implemented (§6.1).** `docs/v2/ui-ux-integrated-spec.md` §6.1 says 「吸着半径は画面px基準とし、通常候補と現在ツールに適合する候補で強さを変える」. The same idea is in `docs/v2/ui-workflows.md`: 「現在ツールに適合する候補を優先し」.
   - No document gives a radius, ratio or rule for tool-suited candidates. The worker contract forbids inventing one, so none was added.
   - The UI-P1-007 acceptance test (`.ai/TASKS.json`, 「Snap 12 logical px」) gives 12 px as a single value. I read that as the normal-candidate radius, so I see no document conflict.
   - If the owner meant 12 px to apply to every candidate, it would conflict with §6.1, and the owner would need to decide.
2. **The tool's required type is not ranked first.** This is required by §4.3 item 1 (「入力中ツールが要求する型」) and by `docs/v2/product-contract.md` PRD-060 (「現在のツールが要求する型を最優先する」).
   - `SnapSettings` has no input for the type the active tool needs, and no tool sends one.
   - The rank currently starts at §6.1 item 1 (endpoint and drawing point).
3. **The 12 px radius combined with the grid can make free placement impossible.**
   - On a square grid, a pointer is never more than spacing / √2 from a grid point.
   - So when grid points are about 17 px or less apart on screen (12 × √2 ≈ 16.97), a grid candidate is always within reach and free placement on the plane never wins.
   - This works against §6.1's 「主点へ常時強く引き寄せず」. It is not fixed in this stage.
4. **Stage 2 and later (not in the Stage 1 scope):**
   - `SnapHysteresis` is not connected to `DrawingSession` yet, so `Reset` is never called on tool switch or cancel.
   - The `S`-key self-test in `V2SelfTestInput.cpp` is still missing.
5. **Performance is unmeasured.** Closest-point snapping samples and refines every curve on every pointer move. Spec §13 asks for a test at the scale of 10,000 wires.
6. **Build and tests were not rerun here** after the comment edit, because approval was blocked. The results above come from the orchestrator's earlier run.
