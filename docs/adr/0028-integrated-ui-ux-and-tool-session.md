# ADR 0028: V2 UI/UXをToolSession中心へ統合する

- Status: Accepted
- Date: 2026-09-12
- Decision owner: project owner
- Supersedes: ADR 0025の固定4モードと、旧UI文書の選択・スナップ操作

## Context

V2には作図、部品、製作、出力の機能が接続されたが、画面と操作は機能追加の順に増えていた。
同じコマンドが上部と右パネルに重複し、モードを変えても以前のツールが残り、
事前選択がなければコマンドを開始できず、EntityIdだけの選択では同一ワイヤー上の複数線分や
端点を保持できない。利用者は機能試験へ到達する前に操作方法を見失っていた。

オーナー提供のUI/UX統合仕様には、意味状態、カーソル、マウス、ToolSession、コンテキストプロパティ、
DPIと画面復元まで一貫した規則がある。一方、固定4モード、板材、Sketch所有、高度な一般CAD機能など、
Wire-first V2の既決定事項と衝突する記述も含まれていた。

## Decision

1. `docs/v2/ui-ux-integrated-spec.md` をV2 UI操作の正本にする。
2. 固定4モードを最終UIの必須構造から外し、メニュー、1段道具バー、左モデルツリー、中央ビューポート、
   右コンテキストプロパティへ統合する。
3. 利用者向け `板材` 概念は復活させない。材料と厚さは部品または製作モデルの属性にする。
4. ワイヤーは3D空間に独立して存在し、Sketchまたは作業平面の所有物にしない。
5. 標準操作順は `ツール -> 対象 -> パラメータ -> 確定` とする。有効な事前選択も同じCommandへ渡せる。
6. 選択はEntityIdだけでなくサブ要素種別、安定SubshapeKeyまたはSegmentId、ヒット位置を保持する。
7. Hover、Selected、Input、Preview、Warning、Errorを意味状態として分離する。
8. 全対話ツールを共通ToolSessionへ段階的に移し、Esc、Enter、Backspace、Ctrl+Zを統一する。
9. Shiftは作図拘束、Ctrlは選択集合、Sは一時スナップ解除とする。
10. スイープ、シェル、一般3Dフィレット、一般アセンブリ、複数文書UIは今回実装しない。

## Consequences

- ADR 0025の4モードは移行用互換UIに限って一時的に残せるが、最終受入前に削除する。
- 既存のモード別コマンド棚と状態機械は段階的に置き換える。機能を消してから後で戻す移行は行わない。
- `SelectionSet`、ビューポートのpick結果、Command有効条件、右パネルは公開契約の更新が必要になる。
- WP-10の製作・出力ロジックは再利用し、WP-14は共通操作基盤と画面統合を所有する。
- V1は比較資料として残すが、V1の所有関係、名前参照、巨大MainWindowは移植しない。
- 現行UIが新受入条件を満たさない箇所は、既に動作していても未達として追跡する。

## Rejected alternatives

### 固定4モードを維持して見た目だけ整理する

モードとツール状態が二重になり、切替後に古いツールが残る原因を温存するため採用しない。

### 全操作を事前選択だけにする

複数入力の順序が分かりにくく、CAD初心者が次に選ぶ対象を把握できないため採用しない。

### 全操作をツール先行だけにする

既に選択した対象へ素早く処理を適用する一般的な操作を不必要に禁止するため採用しない。

### 添付仕様を無修正で採用する

板材、Sketch所有、固定モード、高度な未実装機能がV2の製品契約と衝突するため採用しない。
